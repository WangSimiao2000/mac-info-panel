# Info Panel Rust 跨平台重构需求

## 1. 目标

将纯 Swift/macOS 原型保存在 `legacy/swift` 分支，并在 `main` 重新实现以 Rust 为核心、使用 Slint 构建 UI 的跨平台信息面板。旧版仅作为行为和视觉参考，不提供配置或安装兼容。

目标平台：

- macOS 14 及以上
- Windows 11 及以上
- 主流现代 Linux 桌面，优先支持 Wayland，并保留 X11 兼容路径

首个可发布里程碑以 macOS 功能对齐为准，随后完成 Windows 和 Linux 平台适配。

## 2. 不在首版范围内

- 不允许插件提供任意 Slint、HTML 或 JavaScript UI。
- 不允许插件加载原生 `.dylib`、`.dll` 或 `.so`。
- 不要求三个平台具备完全相同的系统材质或窗口管理语义。
- 不读取或迁移旧 Swift 版本的配置、安装状态或 LaunchAgent。
- 不在首版实现插件间直接通信。

## 3. 应用功能需求

### 3.1 页面与导航

1. 应用必须支持总览、歌词、本机状态和插件页面。
2. 应用必须支持滚轮、触控板、托盘菜单和自动轮播切页。
3. 应用必须保存并验证初始页面；不存在的页面 ID 必须产生可诊断的配置错误，而不是静默回退。
4. 页面较多时，页面指示器必须折叠或滚动，不得溢出窗口。
5. 页面内容必须支持小屏自适应、垂直滚动、长文本截断和可配置展示上限。

### 3.2 显示器与窗口

1. 应用必须支持按名称和稳定硬件标识选择显示器。
2. 未匹配指定显示器时，应优先选择非主显示器，再回退主显示器。
3. 应用必须响应显示器连接、断开、分辨率和缩放变化。
4. macOS 应保持 nonactivating panel、全 Space 可见和避开菜单栏/Dock 的现有行为。
5. Windows 和 Linux 应实现各平台最接近的无焦点信息面板行为，并记录平台限制。

### 3.3 系统指标

1. 提供 CPU、内存、磁盘、网络、系统负载、运行时间和热状态；平台不支持的字段必须显式标记为不可用。
2. CPU 和网络增量计算必须处理计数器回绕、重置和接口变化。
3. 指标采样必须可取消，并在面板隐藏时降低或暂停不必要采样。
4. 卷数量不得硬编码为两项，布局必须处理任意已配置卷。

### 3.4 媒体与歌词

1. macOS 使用 MediaRemote 兼容层或受控的 `media-control` 回退方案。
2. Windows 使用 Global System Media Transport Controls。
3. Linux 使用 MPRIS/D-Bus。
4. 曲目标识应优先使用平台内容标识和播放器标识，再回退到规范化元数据。
5. LRC 必须支持多时间戳、翻译行和格式错误容错。
6. 歌词缓存必须有容量上限、TTL 和过期清理。
7. 不安装或禁用歌词能力时，不得显示歌词页、启动媒体歌词任务或访问歌词服务。
8. 应明确提示歌词查询会向第三方服务发送标题和歌手信息。

## 4. 视觉与无障碍需求

1. 以当前 Swift 版本截图和交互为 macOS 视觉基准。
2. UI 必须通过统一 design tokens 控制颜色、字体、圆角、间距、阴影和动画。
3. 所有插件页面必须由宿主组件渲染，以保持统一风格。
4. macOS 可使用系统模糊或材质适配；Windows 可使用 Mica/Acrylic；Linux 使用 compositor 支持的能力。平台材质不同不得改变信息层级和布局语言。
5. 必须支持 Reduce Motion、文字缩放、键盘可访问性和高对比度。
6. 视觉回归测试必须覆盖基准窗口、小屏、长文本、大量字段、不同 DPI 和 Reduce Motion。

## 5. 插件系统需求

### 5.1 插件格式

插件包扩展名为 `.info-panel-plugin`，入口必须是以下一种：

- `plugin.wasm`：编译型 WASM 插件
- `plugin.lua`：由宿主提供的受限 Lua-in-WASM runner 执行

插件包至少包含：

- `manifest.json`
- `plugin.wasm` 或 `plugin.lua`
- `config.schema.json`（可选）
- `README.md`
- `LICENSE`
- `assets/`（可选且受大小限制）

插件必须声明：

- 唯一 ID
- 名称与版本
- 插件 API 版本
- 最低宿主版本
- 页面元数据
- 所需权限
- 源码地址和许可证

### 5.2 插件运行时

1. 插件使用 WebAssembly 沙箱运行；首版宿主运行时采用 Extism，并通过内部 trait 隔离具体运行时。
2. 插件可以直接提供 WASM，或提供由受限 Lua-in-WASM runner 执行的 Lua 源码；两者具有相同的权限和页面模型边界。
3. 插件只能通过版本化的 `panel-plugin-api` 与宿主通信。
4. 插件返回语义化 `PageModel`，不得返回任意 UI 代码。
5. 插件崩溃、超时或产生非法模型时，只影响自身页面。
6. 宿主必须限制插件执行时间、内存、输出大小、请求频率、缓存容量、文本长度和组件数量。
7. 插件 API 必须支持向后兼容策略和兼容性测试夹具。

### 5.3 权限

插件默认无网络、文件、进程、环境变量和平台 API 权限。

首版可声明能力：

- 通过宿主访问白名单 HTTPS/loopback URL
- 读取自身经过 schema 验证的配置
- 使用有配额的插件私有缓存
- 读取宿主提供的非敏感平台和区域设置

宿主 HTTP 必须执行：

- HTTPS 默认策略
- loopback HTTP 例外
- 域名白名单
- 禁止 URL 凭据
- 禁止或严格控制重定向
- 不保存 Cookie
- 请求和资源超时
- 响应大小上限
- 并发和速率限制

新增权限或扩大域名范围的插件更新必须重新获得用户确认。

### 5.4 MC Ops 插件

1. 当前 Minecraft/MC Ops 页面必须从主仓库移出业务实现，作为独立插件示例。
2. 插件通过宿主 HTTP API 获取状态并转换成统一页面模型。
3. 现有服务端 collector/forced-command 可独立保留，但客户端插件不得执行 SSH 或任意本地命令。
4. MC Ops 插件必须拥有独立源码仓库、版本、许可证、测试和发布产物。

## 6. 插件仓库需求

1. 建立独立插件索引仓库，不与主应用发布生命周期绑定。
2. 索引记录下载 URL、SHA-256、签名、权限、API 版本、最低宿主版本、源码和许可证。
3. 插件二进制优先托管于各自 GitHub Releases，索引仓库只保存审核后的元数据。
4. CI 必须验证 schema、哈希、签名、权限变更和 API 兼容性。
5. 首版只允许安装可信索引中的插件；开发模式可显式加载本地未签名插件，并显示持续警告。

## 7. 配置需求

1. Info Panel 使用独立的 schemaVersion 1 JSONC 配置，不读取旧 Mac Info Panel 配置。
2. 配置解析必须报告字段路径和原因。
3. 配置必须通过版本化 schema 和跨字段规则验证。
4. 同一 Info Panel schema 后续升级时必须使用纯函数迁移，并在写入前备份当前配置。
5. 插件配置与核心配置分离，插件卸载不得删除其数据，除非用户明确要求。
6. 未安装或禁用歌词插件时，不得生成歌词页面或启动相关任务。

## 8. 安全与稳定性需求

1. 所有外部输入在进入状态模型前必须验证。
2. 插件和远端请求不得获得宿主进程的隐式权限。
3. 日志不得记录歌词查询全文、认证信息、URL 凭据或插件私有配置。
4. 调度任务必须支持取消、指数退避和抖动，避免失败任务固定频率重启。
5. 长时间运行测试必须覆盖缓存增长、任务泄漏、插件连续失败和显示器热插拔。
6. 依赖必须执行许可证、安全公告和供应链检查。

## 9. 工程与发布需求

CI 至少执行：

- `cargo fmt --check`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo test --workspace`
- 依赖许可证与安全检查
- 插件兼容性和恶意夹具测试
- macOS、Windows、Linux 构建
- 安装包结构验证
- macOS 签名和公证验证（正式发布）
- 插件索引 schema、哈希和签名验证

README 必须写明：

- 精确最低 Rust 工具链
- 三个平台依赖
- 配置与日志位置
- 插件权限模型
- 第三方歌词隐私边界
- 平台能力差异

## 10. 验收标准

### 里程碑 1：架构骨架

- Cargo workspace 可在 macOS 构建和测试。
- Slint 显示使用 design tokens 的静态面板。
- 示例 WASM 插件可被加载、校验并渲染。
- 非法、超时和越权插件测试通过。

### 里程碑 2：macOS 对齐

- 当前默认三页功能对齐。
- 多显示器、托盘、滚动导航和自动轮播对齐。
- Info Panel schemaVersion 1 配置可被严格验证并给出字段级错误。
- 视觉回归符合批准的容差。
- `--without-lyrics` 类不一致问题不存在。

### 里程碑 3：插件生态

- HTTP JSON 和 MC Ops 可作为插件运行。
- 插件 CLI 可创建、校验、测试和打包插件。
- 独立插件索引仓库可验证并安装插件。

### 里程碑 4：跨平台发布

- macOS、Windows 11 和目标 Linux 桌面可安装运行。
- 平台媒体、托盘、窗口和指标适配通过验收。
- CI 产生可验证安装包。
